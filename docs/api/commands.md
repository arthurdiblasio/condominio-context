# Catálogo conceitual de Commands

Os identificadores abaixo nomeiam intenções de negócio, não endpoints/URLs. Cada command tem um ator (sujeito autenticado ou actor operacional explicitamente atribuível), um recurso/tenant, permission/scope, guardas e resultado. Não há escolha de HTTP, payload ou transporte.

WF-01. |
| `block.create/update/close`, `unit.create/update/close` | Block, Unit; admin tenant | `block.manage`, `unit.update` / tenant, Block, Unit | Parentage no mesmo tenant; vínculos/histórico não apagados | Fatos structurally changed; audit. WF-02/03. |
| `person.create/update/associate` | Person; ator de cadastro | `person.update` (sem `person.create` distinto no catálogo) / tenant e scope mínimo | Finalidade, identificação, duplicidade, privacy e tenant coerentes | Person changed/associated; audit; notification só se policy. WF-04. |

## Regras transversais do command

Todo comando resolve ator, ação, recurso, tenant, Scope e estado; recusa execução se qualquer guarda falhar; não pode aceitar update genérico de status para contornar a state machine. Fatos produzidos e audit/notificação são detalhados em [traceability](./traceability.md) e [idempotency](./idempotency.md).
